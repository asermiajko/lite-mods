# lite-mods — правила для агента

Патчи (CSS + JS) поверх готовых блоков сайтов на конструкторе Ида.Лайт. Доступа к бэку нет: блоки меняются только на клиенте.
Пользователь пишет в чат, что поменять в блоке. Агент правит патч, показывает превью и публикует **только после явного «ок»**.

## Как это устроено
- В админке сайта один раз подключён `loader.js` (GitHub Pages: `https://asermiajko.github.io/lite-mods/loader.js`).
- Загрузчик подключает ОДИН файл сайта `sites/<hostname>.js`. Его собирает `tools/build.py` из `sites/<hostname>.json` (какие блоки включены) и `blocks/<Блок>/{style.css,script.js}`. Стили блока попадают на страницу, только если блок на ней есть.
- Патч применяется к каждому `section.<Имя блока>` после гидратации Nuxt 2. Перерисованные Vue блоки подхватываются автоматически.
- Флаги в адресе сайта: `?dev=1` — черновик с `localhost:3400` (`python3 dev.py`), `?dev=0` — выйти из черновика, `?nomods=1` — сайт без патчей.

## Рабочий цикл
1. **Структура блока.** Прочитать `blocks/<Блок>/snapshot.txt` и `notes.md`. Если снимка нет или он устарел: открыть сайт во встроенном браузере, выполнить `tools/snapshot.js` (подставить имя блока), сохранить результат в `snapshot.txt`.
2. **Правка.** `style.css` и `script.js` в `blocks/<Блок>/`. Новый блок добавить в `sites/<hostname>.json`.
3. **Превью.** `python3 tools/build.py --preview <hostname>`, затем открыть страницу с `?nomods=1` и вставить содержимое `dist/<hostname>.preview.js` через javascript_tool (превью-бандл работает поверх `?nomods=1`, боевые патчи не мешают). Встроенный браузер блокирует localhost с внешних сайтов, поэтому превью идёт через бандл. Когда окно встроенного браузера скрыто, таймеры и CSS-анимации в нём стоят до первого скриншота. Для проверки делать скриншот, а не судить по `getComputedStyle`. Пользователь в своём Chrome может смотреть через `?dev=1` с запущенным `dev.py`.
4. **Проверка.** Скриншоты на десктопе (1280) и мобилке (375), hover-состояния, консоль без ошибок `[lite-mods]`.
5. **Отчёт пользователю.** Что сделано и что посмотреть; спросить, публиковать ли.
6. **Публикация** (только после «ок»): `./publish.sh "сообщение"`. Скрипт поднимает версию манифестов, пересобирает `sites/*.js`, коммитит и пушит. Черновик, который ещё не одобрен, держать в манифесте с `"enabled": false`, иначе он уедет на бой вместе с другими правками. На бою изменение появится через ~1–2 минуты.
7. Дописать в `notes.md`, что изменено и почему.

Откат: `git revert` нужного коммита, затем `./publish.sh`. Выключить патч: `"enabled": false` в манифесте сайта.

## Правила патчей (важно)
- **Всё строго внутри `.ИмяБлока`.** Никаких глобальных стилей.
- **Классы на элементах Vue не добавлять и не удалять**: Vue 2 перезапишет `class` при следующем обновлении. Использовать `data-lm-*` атрибуты и CSS-переменные (`el.style.setProperty('--lm-…')`).
- **Не удалять и не переставлять узлы, которыми управляет Vue.** Свои элементы добавлять можно (например, декоративные), лучше через `::before`/`::after`.
- **Селекторы**: стабильные классы `Блок__TypeN`, `Блок__TypeN__Часть`, `Ida*`/`Classic*`. Классы CSS-модулей с хэшем (`src-components-production-…-2Jmz`) использовать только через `ctx.part('header')` или `[class*="-header-"]`.
- **Цвета и шрифты брать из темы**: `--ui-main-color`, `--ui-main-color-32`, `--ui-font-black-color-8`, `--map-border-radius` и т.п. (заданы на обёртке блока).
- **Скрытие «до появления»** делать только под `[data-lm-ready]`, который ставит `script.js`. Если JS упал, блок выглядит как в оригинале.
- У платформы есть своя анимация `IdaAppear` (`--appear-top`, `--is-visible`). Анимировать вложенные элементы, а не сами обёртки `IdaAppear`.
- Яндекс.Карты: на предках карты не использовать `transform` (ломает клики), только `clip-path`/`opacity`.
- Учитывать `prefers-reduced-motion`: `ctx.reducedMotion` в JS и `@media` в CSS.
- Внешние библиотеки (GSAP и т.п.) только с cdnjs/jsDelivr с точной версией и только если без них никак.

## Свои блоки (в HTML-блоке) — строго в дизайн-системе сайта
У HTML-блока нет контейнера, поэтому повторять разметку штатных блоков:
- обёртка: `padding-block: var(--ui-padding-top, calc(var(--ui-unit) * 12)) …`, на ≤812px × 6; фон `--ui-base-white-color`;
- контейнер: `width: calc(var(--ui-col) * 32); margin: 0 auto`, на ≤812px `width: calc(100% - var(--ui-unit) * 8)`;
- шапка блока: flex «заголовок (ширина 10 колонок) | текст», на ≤812px столбиком;
- заголовок: `--ui-title-font-family`, `ui-unit × 8` (моб. × 5), 120%, 400; текст: `ui-unit × 4` (моб. × 3.5), 150%, `--ui-base-black-color-48`;
- брейкпоинт сайта — 812px; заголовки карточек мельче заголовка блока.
Точные правила снимать со штатного блока на странице (`document.styleSheets` → селектор `*-container-*`, `*-title-*`), а не подбирать на глаз.

## Производительность и мигание
- Патч срабатывает после гидратации Nuxt (~1–1,5 с), когда блок на первом экране уже виден. Не прятать и не переигрывать то, что посетитель уже видит: `ctx.initialLoad === true` — блок был на странице с загрузки. Анимацию «появления» делать только для `!ctx.initialLoad` или для того, что ещё не на экране.
- Весь сайт — 2 запроса: `loader.js` и `sites/<host>.js` (~6 КБ gzip на два патча).

## API патча
```js
window.LiteMods && LiteMods.register('Блок__ClassicTypeN', function (root, ctx) {
  ctx.$('sel'); ctx.$$('sel');      // поиск внутри блока
  ctx.part('advantages');           // элемент CSS-модуля по имени без хэша
  ctx.inView(els, cb, ioOptions);   // cb(el) один раз при попадании в экран
  ctx.initialLoad;                  // блок был на странице с загрузки (уже виден)
  ctx.reducedMotion; ctx.dev; ctx.log('...');
});
```

## Сайты
- `ohqmp.dev-lite.ru` — тестовый сайт, пилот. Сайт в режиме превью: глобальные скрипты не выполняются, загрузчик подключён через HTML-блок внизу главной (см. README). На других страницах патчей нет, пока туда не добавлен такой же блок.

## Как проверить, что загрузчик на странице
`window.LiteMods` существует, `LiteMods.base` = адрес GitHub Pages, у `section.<Блок>` есть атрибут `data-lm-ready`.
Причина, если глобальные скрипты молчат: в коде платформы они выводятся только при `!site.is_preview_mode && site.project.has_balance` (`$nuxt.$store.state.site`).
